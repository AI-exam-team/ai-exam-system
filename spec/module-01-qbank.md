# 模块 01：题库与组卷 (qbank) 规格说明

## 1. 摘要
本模块负责教师主观题（简答题、论述题）的录入、评分点（Rubric）维护，以及试卷的生成。作为 MVP1 的输入入口，本模块负责向下游（exam 模块）输出包含题目、参考答案和严格分值校验的 `DRAFT` 试卷；考试发布、时间窗口与作答由 `exam` 负责。

## 2. 用户故事
- **US-1（建题）**：作为教师，我想要录入包含题干、参考答案和多个评分点的题目，以便系统能基于评分点进行结构化评分。
- **US-2（组卷）**：作为教师，我想要从题库选择题目组成试卷并保存为草稿，以便后续交给考试模块发布。
- **US-3（异常拦截）**：作为教师，如果我写的评分点有歧义或分值算错，我希望系统能拦截我，以便保证后续 AI 阅卷的准确性。

## 3. 验收标准 (AC)
*严格遵循 Given/When/Then 格式，覆盖正常、边界与异常。*

- **AC-1（正常流程：建题与状态）**
  - **Given** 教师处于建题页面
  - **When** 录入一道 10 分的简答题，配置 2 个评分点（各 5 分），描述分别为“答出概念”、“给出示例”，并保存
  - **Then** 系统返回成功，题目入库，状态默认为 `DRAFT`，可流转为 `ACTIVE` 供组卷。

- **AC-2（边界条件：评分点描述含模糊词）**
  - **Given** 教师录入主观题
  - **When** 评分点描述填写为“答出核心概念以及其他合理观点”
  - **Then** 系统应拒绝保存，返回 409 错误码 `RUBRIC_DESCRIPTION_VAGUE`。

- **AC-3（异常流程：分值不匹配）**
  - **Given** 教师配置题目总分为 10 分
  - **When** 但其包含的评分点分值之和为 8 分，点击保存
  - **Then** 系统应拒绝保存，返回 409 错误码 `RUBRIC_SCORE_MISMATCH`。

- **AC-4（正常流程：组卷并保存草稿）**
  - **Given** 教师有两道 `ACTIVE` 题目，分值分别为 40 分和 60 分
  - **When** 教师选择这两道题组成试卷并保存
  - **Then** 试卷以 `DRAFT` 状态保存，总分 100，各题分值继承题目原分值且不可修改；此时不设置 `startAt/endAt`，等待 `exam` 发布。

## 4. 功能需求 (FR)
- **FR-1 题目管理**：支持创建简答题/论述题，包含题干、参考答案、总分。
- **FR-2 评分点管理**：题目必须包含至少 1 个评分点，每个评分点包含要点描述和分值。同一题内评分点分值之和必须等于题目总分。
- **FR-3 词法校验**：保存题目时，系统自动检测评分点描述，禁止出现“以及、等等、酌情、其他合理”等不可判定表述。
- **FR-4 组卷**：从 `ACTIVE` 的题目中选题组建试卷，题目分值不可修改，必须继承题目原有分值；组卷结果以 `DRAFT` 保存，不设置 `startAt/endAt`（由 `exam` 在发布时设置）。试卷总分由各题分值汇总，不接受手工填写。
- **FR-5 试卷交接**：组卷完成后试卷状态为 `DRAFT`，仅 `DRAFT` 试卷可交接给 `exam`。发布（`DRAFT → PUBLISHED`）、关闭（`PUBLISHED → CLOSED`）及时间窗口管理均属于 `exam`，本模块不实现。

## 5. 非功能需求 (NFR)
- **数据一致性**：必须保证题目分值与评分点分值和的一致性，必须通过数据库事务或代码逻辑严格校验。
- **接口响应**：题目保存与组卷保存操作响应时间 ≤ 2 秒。
- **错误响应规范**：所有校验失败必须返回统一的 JSON 格式，包含 `code` 和 `message`，禁止使用 HTTP 200 表示业务失败。

## 6. 边界与异常
| 场景 | 预期行为 | 对应 AC / 契约错误码 |
|------|----------|----------------------|
| 评分点分值之和 ≠ 题目总分 | 拒绝保存 | AC-3 / `RUBRIC_SCORE_MISMATCH` (409) |
| 评分点描述包含不可判定词 | 拒绝保存 | AC-2 / `RUBRIC_DESCRIPTION_VAGUE` (409) |
| 组卷时尝试修改单题分值 | 拒绝，使用题目原分值 | FR-4 / — |
| 使用非 `ACTIVE` 题目组卷 | 拒绝加入试卷 | FR-4 / — |

## 7. Non-Goals (不做)
- 不支持客观题（单选/多选/判断）。
- 不包含管理员审核流；教师直接发布由 `exam` 负责。
- 不支持组卷时临时修改单题分值（需回原题修改后重新组卷）。
- 不支持题目版本管理与历史快照（具体参考契约 C-01 留待后续）。
- 不做考试发布、时间窗口设置、自动交卷与答卷管理（属于 `exam`）。

## 8. 架构不确定点（后续 ADR）
**认领项：C-01 组卷引用题目还是保存快照？**
- **问题描述**：试卷（Paper）由 `exam` 发布（PUBLISHED）后，如果教师修改了原题目（Question）的题干、参考答案或评分点，是否会影响已经发布的试卷和正在进行的考试？
- **当前诉求**：若采用“动态引用”，改题会破坏历史考试的一致性；若采用“保存快照”，则需考虑数据冗余和存储成本。
- **下一步计划**：本周暂不定论，将于后续架构设计阶段，通过提交 `/adr/ADR-001-qbank-snapshot.md` 决策记录，确定具体方案（引用或快照，以及快照包含的字段）。
