# ADR-003：AI 初评的调用方式、超时重试与幂等

## 背景

AI 初评是整条链路唯一依赖外部模型、耗时与费用都不可控的环节：

- 同一道题可能被教师重复点击、网络重试或前端重复提交，若没有幂等，会重复计费并可能用后返回的结果覆盖已有结果。
- 模型可能超时、限流、返回无法解析的 JSON、评分点对不上或分数越界；契约要求整题拒绝，不允许部分采纳，也不允许失败自动记 0 分。
- 教师在 AI 调用进行中就可能开始人工复核；迟到的 AI 响应不得覆盖 `reviewedScore`。
- 课程约束：单体应用、仅 MySQL、**禁止 Redis / 消息队列 / 微服务**（`context.md` 第 5 节），因此不能用分布式锁或 MQ 做任务承载。
- `agent-rules.md` AR-6.7 要求持久化模型名、提示词版本、原始响应与评分点命中，当前 `GradeResult` 契约尚未定义这些字段。

不决策的后果：重复调用导致费用失控、迟到响应覆盖教师确认分、第 9 周无法拆出可测试的初评任务。

## 决策

**候选决策：MVP1 采用「逐题同步 HTTP + 数据库状态占位（PENDING）+ `(answerSheetId, questionId)` 唯一约束 + 条件更新」，不引入异步队列或批量 grading API。** 集成负责人已于 2026-11-28 确认该方向；本 ADR 仍需 grading 组评审后才能标记 Accepted。

1. **唯一键与状态**
   - `GradeResult` 以 `(answerSheetId, questionId)` 唯一。
   - 触发前读取现状：`SUCCEEDED` 直接返回已有结果，不再调用模型；`PENDING` 返回 409 `AI_GRADING_IN_PROGRESS`；`NOT_STARTED` / `FAILED` 才允许发起。
   - 发起时用条件更新把状态从 `NOT_STARTED/FAILED` 置为 `PENDING`（比较并设置），并原子增加 `attemptCount` / `currentAttempt`；只有更新成功者可以调用 DeepSeek，避免并发双调用。

2. **同步调用与超时**
   - 初评请求在 HTTP 请求内完成模型调用；后端模型调用超时 **30 秒**（可配置），前端请求超时 **65 秒**，保证后端先于前端超时。
   - SP-01 现有 21 次调用得到结构校验 21/21、P95 0.794 秒、超时 0/21、总费用 0.01238612 元；这只是 3 种合成样本的小样本观察。PR #52 当前仍有两条 `CHANGES_REQUESTED`，样本分母、证据归档和超时模拟尚待复核；在评审完成前，不把这些数据写成已接受的性能验收结论。
   - 超时返回 502 `AI_SERVICE_TIMEOUT`，该题置 `FAILED`，保留人工复核通道。

3. **有限重试**
   - 每个 `(answerSheetId, questionId)` 最多发起 **3 次实际模型调用**。首次调用、自动重试、教师再次触发后发起的调用均计数。每次请求最多自动重试 1 次且仅限可重试网络异常，发起前原子占用剩余额度。复用成功结果、请求校验失败及 PENDING 拒绝均不计数。耗尽后继续开放人工复核。
   - 成功结果永久复用，不重复调用；失败不等于 0 分。

4. **输出校验（整题原子）**
   - 评分点 ID 完整、无重复、无陌生 ID；字段类型正确；`hit` 与二值得分一致；逐点得分之和等于 `aiScore` 且落在 `[0, 题目分值]`。
   - 任一校验失败：整题不写入任何可用建议分，置 `FAILED`，不修补、不部分采纳。
   - 校验优先级：结构 / 类型 / ID / 命中与合计一致性错误返回 502 `AI_OUTPUT_INVALID`；结构可解析且为数值但越界时优先返回 502 `AI_SCORE_OUT_OF_RANGE`，以细化 v0.1 R6 的宽泛映射。

5. **迟到响应保护**
   - 写回结果时使用条件更新：仅当 `reviewedScore IS NULL` 且 `aiStatus = PENDING` 且调用尝试号匹配时写入。
   - 教师可在任一 AI 状态（含 `PENDING`）完成人工复核。若复核与模型调用并发，人工复核通过条件更新将当前尝试置为 `FAILED`，`lastErrorCode=AI_RESULT_DISCARDED`；迟到响应只记审计，不覆盖 `reviewedScore`、`aiScore` 或当前尝试状态，并向该次初评请求返回 409 `AI_RESULT_DISCARDED`。

6. **审计字段（满足 AR-6.7）**
   - 新增服务端持久化字段：`modelName`、`promptVersion`、`rawResponse`、`attemptCount`、`lastErrorCode`、`requestedBy`、`requestedAt`、`currentAttempt`。
   - 这些调用审计字段不出现在学生 API，教师 `GradeResult` 默认也不返回 `rawResponse`；原始响应中的密钥、地址等敏感信息不入库，只保存脱敏的模型输出正文。

7. **发布边界与触发粒度（集成负责人候选决策）**
   - API 只暴露单题初评；教师端整卷操作由前端逐题调用，单题是重试与错误呈现单位。grading 组须评审该调用粒度。
   - 成绩仅在试卷 `CLOSED`、至少有一份 `SUBMITTED` 答卷且全部逐题确认后发布。发布后锁定确认分；重复发布返回原 `publishedAt`。
   - grading 以唯一 `paperId` 的 `GradePublication` 记录 `publishedAt` / `publishedBy`；不存在记录表示未发布。READY 从考试、答卷和复核状态推导，不单独存储。`finalScore` 按确认分计算，不存重复副本。

8. **同步方案的失效条件**
   - 在 grading 组确认样本与统计口径后，若可复核的 SP-01 实测 P95 延迟 > 30 秒，或结构校验失败率 > 10%，本 ADR 修订为「202 受理 + `aiStatus=PENDING` 轮询」的异步方案，并同步更新 OpenAPI 与前端交互；不在本 ADR 内提前实现异步。

## 备选方案

| 方案 | 优点 | 缺点 | 未采用原因 |
| --- | --- | --- | --- |
| A. 同步调用，无幂等 | 实现最简单，无额外状态 | 重复点击/重试导致重复计费；迟到响应可覆盖复核分；并发下无法判断谁在调用 | 违反幂等与费用控制要求，风险不可接受 |
| B. 逐题同步调用 + 数据库状态占位 + 唯一约束（**候选采用**） | 仅用 MySQL；幂等与迟到保护可测试；实现量可控；符合单实例 MVP | 教师需等待；占用一个 HTTP 线程；超时阈值依赖后续复核的实测 | grading 组评审前不标为最终接受 |
| C. 异步任务（`@Async` / 线程池）+ 202 + 前端轮询 | 不阻塞请求；可后台重试；体验更好 | 需处理任务重启丢失、PENDING 僵尸状态、轮询接口与前端状态机；第 10 周工作量明显增加 | MVP1 单实例、演示规模小，先以 B 降低实现风险；作为 SP-01 触发后的回退方案 |
| D. Redis 分布式锁 / 消息队列 | 多实例下最强 | 课程明确禁止 Redis、MQ、微服务 | 范围红线，直接排除 |

**候选理由**：MVP1 是单体、使用 MySQL，逐题结果已有天然幂等键；异步 202 还需轮询、任务恢复和部分失败语义。SP-01 的小样本延迟观察支持先验证同步路线，但证据尚未通过完整评审，因此 30 秒超时和失败率门槛保留为回退条件，不宣称模型可靠性已经验收。

## 后果

### 正面影响

- 同一题最多一次有效模型调用，成功结果复用，费用可控。
- 重复触发、并发触发、迟到响应都有确定行为，可直接写出 AC 与测试用例。
- 只依赖 MySQL，技术栈不越界，第 9 周可拆成「状态占位 + 调用 + 校验 + 写回」四个可测任务。

### 负面影响 / 代价

- 初评请求会阻塞较长（最长 30 秒）；教师端必须展示等待状态并禁止重复点击。
- 若进程在 `PENDING` 期间崩溃，可能留下僵尸状态；MVP1 采用「超过超时阈值的 `PENDING` 允许条件重置为 `FAILED`」的兜底，不引入调度框架。
- 需要契约升版：新增错误码与审计字段；`contract-v0.3.md` / `openapi.yaml` 当前是评审草案，旧版 `contract-v0.1.md` 的 `GradeResult` 字段不足。
