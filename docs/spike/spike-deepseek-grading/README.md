# SP-01 DeepSeek 结构化输出、延迟与费用

主执行：左恩东。复核：王麒博。认领日期：2026-11-18。[Issue #33](https://github.com/AI-exam-team/ai-exam-system/issues/33)

## 验证问题

DeepSeek 逐点评分的 JSON 能否稳定通过评分契约校验？端到端 P95 延迟、超时率和单次费用能否支撑 ADR-003 的同步调用方案？

## 假设

结构校验通过率至少 90%，P95 不超过 30 秒，超时率不超过 5%，可按实际 token 用量估算费用。以上是待验证阈值。

## 步骤

1. 准备合成简答、论述及空答案样本，记录模型名、提示词版本、环境与超时设置。
2. 按 [SP-01 计划](../plan.md#2-sp-01-deepseek-结构化评分输出延迟与费用) 每样本调用 7 次，保留全部 21 条记录。预先记录 20 次统计口径及排除规则，超时、解析失败、校验失败均如实计数。
3. 核对评分点 ID 完备且唯一、字段类型、命中与二值得分、总分范围及合计。记录每次耗时、错误类别、输入输出 token 和费用估算依据。
4. 单独模拟超时与非 JSON 输出，不混入正常样本统计。证据脱敏后归档，密钥使用环境变量。
5. 王麒博复核样本数、统计分母、P95 计算口径与费用来源。一天时间盒到期停止，记录已完成样本与限制。

## 结论

结论：可行。

2026-11-22 完成 21 次真实调用（3 个合成样本 × 7 次；提示词版本 SP01-2026-11-22；客户端超时 30 秒）。请求体 `model` 为 `deepseek-chat`（窗口输出第一行），DeepSeek 控制台 2026-11-22 账单的 `model` 列为 `deepseek-flash`（空闲时段计价）；两处名称按各自来源如实记录，以账单为费用依据，不自行推断别名关系。

| 指标 | 实测值 | 口径 / 依据 |
| --- | --- | --- |
| 结构校验通过率 | 100%（21/21；20 次口径 20/20） | 目标 ≥ 90%，plan.md:56 |
| P95 延迟 | 0.794 秒 | 20 次有效样本，最近秩法 ceil(0.95×20)-1；目标 ≤ 30 秒，plan.md:57 |
| 超时率 | 0.0%（0/21） | 目标 ≤ 5%，plan.md:57 |
| 单次费用估算 | 0.000589815 元（21 次合计 0.01238612 元） | DeepSeek 控制台账单实际扣费，计算过程见下段 |

费用口径：`deepseek-flash` 空闲时段，输入缓存未命中 4507 token × 1 元/百万 = 0.004507 元、输入缓存命中 3956 token × 0.02 元/百万 = 0.00007912 元、输出 1950 token × 4 元/百万 = 0.0078 元，合计 0.01238612 元；。输入合计 8463 / 输出 1950 token。

数据来自 21 次真实调用的窗口输出与 DeepSeek 控制台 2026-11-22 导出的账单。21 次全部通过 ADR-003 第 4 条校验，无失败类型。按 plan.md:51 单独模拟的超时与非 JSON 输出不混入 21 次统计，非 JSON 被识别为 `NON_JSON`；超时模拟的耗时数值因脚本中断未落盘，此处不填数字。

王麒博复核（样本数、统计分母、P95 计算口径与费用来源，见本文件第 19 行）：待复核。

影响：P95 0.794 秒 < 30 秒、结构校验失败率 0% < 10%，未触发 ADR-003:56 的异步回退条件，同步调用方案可维持；30 秒阈值取得实测支撑。按组长要求，本结果已同步回填 ADR-003（第 36 行 30 秒阈值、第 88 行 SP-01 勾选项）；ADR 属契约类文件，按 `agent-rules.md` AR-2.2 走独立 PR 并由集成负责人评审。
