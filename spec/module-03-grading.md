## 1. 摘要

本模块接收考试模块已提交的答卷，由教师触发 DeepSeek 按题库已有评分点生成建议分与理由。教师逐题采纳、修改或驳回 AI 建议并填写确认分；整场所有已提交答卷的所有题均复核后，由教师统一发布成绩。学生只能查看本人已发布的确认分与复核意见。

系统只有教师、学生两种业务角色，题型仅支持简答题 `SHORT_ANSWER`、论述题 `ESSAY`。AI 只辅助评分，不自动定分，也不自动发布成绩。

### 1.1 上下游交接

| 来源 / 去向 | 数据与责任 | 本模块约束 |
| --- | --- | --- |
| qbank → grading | 题干、参考答案、题目分值、评分点 ID / 描述 / 分值 | 只读取约定数据，不修改题目或重新分配评分点分值；历史版本取值待 C-01 |
| exam → grading | `AnswerSheet.status=SUBMITTED`，答卷 ID、试卷 ID、学生 ID、逐题答案 | 接收手动或自动交卷结果；不改变答案、提交方式及提交时间，不处理草稿保存 |
| grading → 教师 | 每题 AI 状态、逐点评分依据、AI 建议分、教师确认分及复核信息 | 只允许试卷创建教师访问与操作 |
| grading → 学生 | 已发布的本人逐题 `reviewedScore`、`reviewComment` 及由确认分汇总的总分 | 未发布不可见；不返回 AI 内部结果或其他学生数据 |

一份 `Paper` 对应一场考试。考试发布和截止由 exam 负责；成绩发布由 grading 负责。二者的“已发布”不是同一个状态。

### 1.2 必需的契约与术语

- `GradeResult` 按 `(answerSheetId, questionId)` 唯一，一份答卷每道试题最多一份评分结果。
- `aiStatus` 仅有 `NOT_STARTED`、`PENDING`、`SUCCEEDED`、`FAILED`。范围文档中的“AI_FAILED”是失败场景描述，落到实体字段时使用 `aiStatus=FAILED`，不新增枚举。
- AI 成功结果包含 `rubricHits`、`aiScore`、`aiReason`。每个命中项含 `rubricItemId`、`hit`、`score`、`reason`；每个评分点恰好出现一次。
- 评分点采用二值规则：命中得该点满分，未命中得 0 分。`aiScore` 等于逐点得分之和。评分点分值来自题库，不由 AI 创建或调整。
- 教师复核记录 `reviewedScore`、`reviewedBy`、`reviewedAt`，可填写学生可见的 `reviewComment`。确认分为 `[0, 题目分值]` 内整数；教师确认分不受 AI 二值命中组合限制。
- 成绩逻辑状态为 `NOT_READY → READY → PUBLISHED`；不是 `AnswerSheet.status` 或 `Paper.status` 的新枚举。其存储表达由后续契约 / 设计明确。
- `finalScore` 仅在成绩发布后由该答卷各题 `reviewedScore` 汇总；发布前不得写入，不独立维护另一份成绩表。

## 3. AC（验收条件）

### 3.1 共用验收数据与方式

准备教师 T1、T2 和学生 S1、S2。T1 的试卷 P 含 Q1（简答题 10 分，评分点 R1=6、R2=4）、Q2（论述题 10 分，评分点 R3=10），总分 20。S1、S2 均有已提交答卷；另准备独立草稿答卷测试拒绝路径。除专门测试发布边界外，发布用例在考试已结束、自动交卷完成后执行。

模型结果、超时及非法响应使用可控制的替身测试，确保预期值可复现；另记录一次真实 DeepSeek 调用的端到端证据。真实模型输出不要求每次完全相同，不能以一次调用宣称评分准确率达标。以下是待执行验收条件，并非已通过的测试记录。

### 3.2 可执行条件

| AC-13 重复与迟到请求 | 同一题重复触发，或已有 reviewedScore 后到达迟到 AI 响应；已发布成绩再次收到发布请求 | 处理请求或回调 | 每题仍只有一个 GradeResult，确认分不被 AI 覆盖；重复发布不改变已发布分数或产生第二份成绩；PENDING 请求、失败重试及重复发布的具体响应待第 6.3 节确定 |

## 6. 边界与异常

### 6.1 已有错误码与处理

| 场景 | HTTP / code | 必须保持的结果 |
| --- | --- | --- |
| 未登录 / JWT 失效 | 401 `UNAUTHORIZED` | 无数据访问、调用或写入 |
| 访问非本人权限资源 | 403 `FORBIDDEN` | 不泄露他人答案或成绩 |
| 答卷不存在 | 404 `ANSWER_SHEET_NOT_FOUND` | 不创建孤立评分结果 |
| DeepSeek 超时 | 502 `AI_SERVICE_TIMEOUT` | 最终失败标记 FAILED，保留人工通道 |
| JSON 不可解析、评分点不匹配、结构不完整 | 502 `AI_OUTPUT_INVALID` | 整题拒绝，不部分采纳 |
| AI 分数越界 | 502 `AI_SCORE_OUT_OF_RANGE`，待统一契约 R6 措辞 | 不截断成边界分或自动记零 |
| 未完成整场复核即发布 | 409 `GRADE_NOT_FULLY_REVIEWED` | 不发布、不提前写 finalScore |
| 学生查询未发布成绩 | 403 `SCORE_NOT_PUBLISHED` | 不返回任何成绩分值 |

上表是业务错误映射，不强行决定 AI 请求是同步还是异步。异步实现需在 OpenAPI 中区分“任务受理成功”和“模型处理失败”，不能把后者显示为评分成功。

### 6.2 关键边界

1. **零分与缺失分不同**：确认分为 0 表示已复核；null、缺字段、缺评分记录均不表示已复核。
2. **AI 失败与教师复核独立**：FAILED 题可具有有效 reviewedScore；不得为使成绩发布而把 aiStatus 改成 SUCCEEDED。
3. **部分题失败**：保留其他题成功建议，每个失败题都必须取得教师确认分后才能满足整场发布条件。
4. **初评完成不等于复核完成**：即使 AI 给满分也不得自动填入 reviewedScore；教师只打开页面也不算确认。
5. **数据版本边界**：已发布试卷的结构、分值、时间不可改；题目本体与 rubric 的历史版本取值仍依赖 C-01，本文不自行承诺快照或动态引用。
6. **状态名称隔离**：Paper.PUBLISHED 是考试发布，成绩 PUBLISHED 是结果发布；AnswerSheet 始终使用 DRAFT / SUBMITTED，不新增 GRADED 等跨模块状态。

### 6.4 与前两组的配合及冷启动交接

本次 v0.2 根据左恩东提供的第 1 轮冷启动记录修订。该轮针对 v0.1，结论为无核心偏差，发现初评触发粒度描述不清。新增 G-08：由 grading 与集成负责人在接口冻结前确认逐题 / 整卷触发入口、批量时的部分失败反馈与重试单位。该项现登记为待决议，未以修订代替团队确认。原始回答和第 1 轮结论保留在冷启动记录，v0.2 尚未重新冷启动。

补充一致性核查：`agent-rules.md` AR-6.7 要求保存模型名、提示词版本、原始响应与评分点命中，而当前 GradeResult 契约尚未定义前三者字段。由集成与 grading 在接口设计前明确记录位置及访问权限，保留 AI 建议与教师确认分的既有分离规则。

- 对 qbank：沿用题目分值和 rubric 二值规则，不接管建题、组卷或考试发布；C-01 的决议需通知 grading。
- 对 exam：只接收 SUBMITTED，支持 MANUAL / AUTO；沿用交卷后只读，不新增考试实体、不重做自动交卷。双方共同确认 G-01。
- 主笔交付：本文件七章与全部 AC；针对冷启动暴露的歧义修订本文并标版本，不代写验证结论。

- 冷启动记录应注明所用 spec 版本 / 提交号；不能把本文已显式列出的未决项误称为已解决，也不能预先写“无偏差、全部通过”。现有第 01、02 组文件保持原样。

## 7. Non-Goals（本期不做）

1. 不做客观题自动判分，仅处理简答、论述题；AI 评分点不支持区间分，需要部分得分时由题库拆细评分点。
2. 不做 AI 出题、错题讲解、AI 自动定分或自动发布、多模型对比与模型训练；模型服务仅 DeepSeek。
3. 不负责题库创建与修改、组卷、考试发布、计时、保存答案、手动 / 自动交卷；不修改已提交答案。
4. 不新增管理员、账号自助注册、密码找回、排名、统计报表、监考、通知推送或成绩导出模块。
5. 不新增 Redis、消息队列、微服务、第二数据库或独立成绩表；不在本规格提前确定接口路径、表结构或 ID 算法。
6. 不承诺题目版本管理、多次考试复用、补考、成绩申诉工作流或完整复核历史系统。第 6.3 节未决项不等于已纳入这些扩展功能。
