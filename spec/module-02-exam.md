## 1. 摘要

本模块负责试卷发布后的考试生命周期：教师发布考试，学生在时间窗口内进入考试、作答并保存草稿、手动或自动交卷。作为 MVP1 的中游，本模块向下游 `grading` 输出状态为 `SUBMITTED` 的答卷，不承担题目维护、AI 评分与成绩发布。

## 2. 用户故事

- **US-1（发布考试）**：作为教师，我想要把已组好的试卷在指定时间窗口内发布，以便学生在正确的时间参加考试。
- **US-2（限时作答）**：作为学生，我想要在考试窗口内作答并看到倒计时，以便在规定时间内完成考试。
- **US-3（答案不丢）**：作为学生，我希望作答内容被自动保存、刷新后能续答，以便意外断线不会让我重做。
- **US-4（交卷与异常反馈）**：作为学生，我想要明确知道自己是否交卷成功、为什么无法作答，以便不会重复提交或误判考试状态。

## 3. 验收标准 (AC)

*严格遵循 Given/When/Then 格式，覆盖正常、边界与异常。*

- **AC-1（正常流程：发布考试）**
  - **Given** 教师持有一张 `DRAFT` 试卷，含 2 道题、总分 100，且 `startAt < endAt`
  - **When** 教师点击发布
  - **Then** 试卷状态变为 `PUBLISHED`，`publishedAt` 为服务端时间，学生端在时间窗口内可见该考试

- **AC-2（边界条件：首次进入与重复进入）**
  - **Given** 考试已 `PUBLISHED`，当前时间在 `[startAt, endAt)` 内，学生尚无答卷
  - **When** 学生首次进入考试
  - **Then** 系统创建一份 `DRAFT` 答卷，`startedAt` 为服务端时间；再次进入时返回同一份答卷，不新建

- **AC-3（正常流程：草稿保存与续答）**
  - **Given** 学生已有一份 `DRAFT` 答卷，并作答了第 1 题
  - **When** 自动保存成功后学生刷新页面或重新登录
  - **Then** 第 1 题内容原样回显，`savedAt` 为服务端时间；未作答的题目保持为空

- **AC-4（正常流程：手动交卷）**
  - **Given** 学生答卷为 `DRAFT`，当前时间在考试窗口内
  - **When** 学生点击交卷并确认
  - **Then** 答卷状态变为 `SUBMITTED`，`submitType=MANUAL`，`submittedAt` 为服务端时间，答卷进入只读

- **AC-5（边界条件：到点自动交卷）**
  - **Given** 学生答卷为 `DRAFT`，到达 `endAt` 时仍未交卷
  - **When** 服务端执行自动交卷
  - **Then** 答卷状态变为 `SUBMITTED`，`submitType=AUTO`，`submittedAt=endAt`，以最后一次成功保存的答案为准

- **AC-6（异常流程：重复交卷）**
  - **Given** 学生答卷已为 `SUBMITTED`
  - **When** 学生再次提交交卷请求（包括网络重试）
  - **Then** 返回 409 `EXAM_ALREADY_SUBMITTED`，答卷内容、`submittedAt` 与总分均不改变；前端按“已交卷”展示

- **AC-7（异常流程：窗口外操作）**
  - **Given** 当前时间早于 `startAt` 或已到达/超过 `endAt`
  - **When** 学生尝试进入考试、保存草稿或交卷
  - **Then** 返回 403 `EXAM_NOT_STARTED` 或 403 `EXAM_CLOSED`，不创建、不修改答卷

- **AC-8（异常流程：发布校验）**
  - **Given** 试卷为空、总分与各题之和不一致，或 `startAt >= endAt`
  - **When** 教师点击发布
  - **Then** 拒绝发布，分别返回 409 `EMPTY_PAPER`、`PAPER_SCORE_MISMATCH`、`INVALID_EXAM_WINDOW`

- **AC-9（异常流程：越权与不存在）**
  - **Given** 学生 A 已登录
  - **When** A 请求学生 B 的答卷，或请求不存在的答卷
  - **Then** 分别返回 403 `FORBIDDEN` 与 404 `ANSWER_SHEET_NOT_FOUND`，不泄露他人答卷内容

- **AC-10（异常流程：自动保存失败可恢复）**
  - **Given** 学生正在作答，自动保存请求连续失败
  - **When** 前端按 1s / 2s / 4s 重试 3 次仍失败
  - **Then** 页面显示「未保存」状态与「重试」入口，作答内容仍保留在当前页面；网络恢复后重试成功，`savedAt` 更新且未保存状态消失

- **AC-11（异常流程：交卷时不丢答案）**
  - **Given** 最后一次自动保存失败，学生点击交卷
  - **When** 提交交卷请求
  - **Then** 请求携带当前全部作答，服务端在同一事务内保存答案并置为 `SUBMITTED`；若交卷请求本身失败，则答卷保持 `DRAFT`，前端提示失败且不显示「已交卷」

## 4. 功能需求 (FR)

- **FR-1 发布考试**：仅允许 `DRAFT` 试卷发布为 `PUBLISHED`；发布前校验试卷至少 1 题、总分等于各题分值之和、`startAt < endAt` 且 `endAt` 未过期；发布后试卷结构、分值与时间窗口不可修改。
- **FR-2 考试可见性**：学生只能看到 `PUBLISHED` 状态的考试；未发布或已 `CLOSED` 的试卷不对学生暴露。
- **FR-3 创建答卷**：学生首次进入窗口内的已发布考试时，创建一份 `DRAFT` 答卷；同一学生同一试卷只能有一份答卷，重复进入返回已有答卷。
- **FR-4 草稿保存**：支持按题保存作答内容，以服务端接收时间为 `savedAt`；重复保存覆盖旧内容；答卷 `SUBMITTED` 后拒绝任何保存；保存失败按 NFR 的重试策略处理，重试耗尽后允许学生手动重试或直接交卷。
- **FR-5 手动交卷**：学生确认后把答卷从 `DRAFT` 改为 `SUBMITTED`，记录 `submittedAt` 与 `submitType=MANUAL`；交卷后答卷只读。
- **FR-6 自动交卷**：到达 `endAt` 仍未交卷的答卷，由服务端置为 `SUBMITTED`，`submitType=AUTO`，`submittedAt=endAt`；以最后成功保存的答案为准，未保存内容不阻塞交卷。
- **FR-7 窗口控制**：所有作答、保存、交卷操作以**服务端时间**判定是否在 `[startAt, endAt)` 内。
- **FR-8 身份与越权**：学生身份取自 JWT，不接受请求体传入的 `studentId`；访问答卷时校验归属，越权返回 403。
- **FR-9 交卷幂等**：手动交卷与自动交卷并发到达时，只允许一次有效状态迁移，重复请求返回 409，不产生第二份答卷。

## 5. 非功能需求 (NFR)

- **时间权威**：考试窗口、`startedAt`、`submittedAt`、`savedAt` 一律以服务端时间为准，不信任客户端时间。
- **幂等与一致性**：答卷唯一性由数据库唯一约束保证；交卷使用条件更新，保证重复请求不改变已提交内容。
- **自动保存与重试**：作答过程中自动保存间隔不超过 30 秒，并在输入失焦、切题与交卷前触发。保存失败（网络异常或 5xx）时，前端按 1s / 2s / 4s 退避重试，最多 3 次；仍失败则在页面持续显示「未保存」状态与手动重试入口，不得静默丢弃，也不得显示为已保存。
- **交卷兜底**：手动交卷请求必须携带当前全部作答内容；服务端在同一事务内保存答案并置为 `SUBMITTED`，避免最后一次自动保存失败导致答案丢失。
- **失败可见**：交卷请求失败时保持 `DRAFT`，前端明确提示失败原因并允许重试；未收到成功响应前不得展示「已交卷」。
- **接口响应**：发布、保存、交卷接口正常响应时间 ≤ 2 秒（不含网络与数据库异常）。
- **错误响应规范**：所有失败返回统一 JSON，包含 `code` 与 `message`，禁止用 HTTP 200 表示业务失败。
- **数据安全**：学生只能读写本人答卷；教师只能查看本人创建试卷的答卷。

## 6. 边界与异常

| 场景 | 预期行为 | 对应 AC / 契约错误码 |
| --- | --- | --- |
| 未到 `startAt` 进入考试 | 拒绝并提示未开始 | AC-7 / `EXAM_NOT_STARTED` (403) |
| 到达或超过 `endAt` 仍操作 | 拒绝作答与保存 | AC-7 / `EXAM_CLOSED` (403) |
| 同一学生重复进入考试 | 返回已有答卷，不新建 | AC-2 / — |
| 同一学生重复交卷 | 拒绝，内容不变 | AC-6 / `EXAM_ALREADY_SUBMITTED` (409) |
| 交卷后再次保存草稿 | 拒绝，答卷只读 | AC-6 / `EXAM_ALREADY_SUBMITTED` (409) |
| 自动保存失败 | 按 1s/2s/4s 重试最多 3 次，仍失败显示「未保存」 | AC-10 / — |
| 自动保存重试期间网络恢复 | 下一次重试成功后清除未保存状态 | AC-10 / — |
| 最后一次自动保存失败后交卷 | 交卷携带全部答案，事务保存后置 `SUBMITTED` | AC-11 / — |
| 交卷请求失败 | 保持 `DRAFT`，提示重试 | AC-11 / — |
| 手动交卷与自动交卷同时发生 | 仅一次状态迁移，另一次按重复交卷处理 | AC-6、FR-9 / `EXAM_ALREADY_SUBMITTED` (409) |
| 发布空试卷 | 拒绝发布 | AC-8 / `EMPTY_PAPER` (409) |
| 发布时总分不一致 | 拒绝发布 | AC-8 / `PAPER_SCORE_MISMATCH` (409) |
| 发布时 `startAt ≥ endAt` | 拒绝发布 | AC-8 / `INVALID_EXAM_WINDOW` (409) |
| 访问他人答卷 | 拒绝并记录 | AC-9 / `FORBIDDEN` (403) |
| 请求不存在的答卷 | 返回不存在 | AC-9 / `ANSWER_SHEET_NOT_FOUND` (404) |
| 自动交卷时存在未保存内容 | 以最后保存内容交卷，不阻塞流程 | AC-5 / — |

## 7. Non-Goals (不做)

- 不支持客观题（单选/多选/判断）及自动判分。
- 不做监考、防作弊、人脸识别、防切屏、断网检测。
- 不做题目与评分点维护（属于 `qbank`）。
- 不做 AI 评分、教师复核与成绩发布（属于 `grading`）。
- 不做选课、班级、参与名单；MVP1 已发布考试对全体学生可见（见第 8 节契约缺口）。
- 不做补考、重开考试、延长截止时间、一试卷多场考试。
- 不做交卷后的改卷、撤销交卷。
- 不做站内通知、短信或邮件提醒。

## 8. 架构不确定点（后续 ADR）

### 8.1 认领项：C-03 并发交卷与自动交卷的幂等实现

- **问题描述**：手动交卷、网络重试与 `endAt` 自动交卷可能同时到达，若没有并发控制，会出现重复提交、覆盖 `submittedAt` 或生成第二份答卷。
- **候选方案**：
  1. `(paperId, studentId)` 唯一索引 + 条件更新 `UPDATE ... WHERE status='DRAFT'`；
  2. 悲观锁 `SELECT ... FOR UPDATE`；
  3. 应用层分布式锁（本课程禁止 Redis，需另行论证，不推荐）。
- **下一步计划**：由 `exam` 组在第 8 周提交 `/adr/ADR-002-exam-submit-idempotency.md`，明确方案、失败重试语义与测试方式。

### 8.2 自动交卷的触发方式

- **问题描述**：契约要求“到 `endAt` 自动交卷”，但未规定定时任务批量处理还是学生下次请求时惰性触发。
- **待定原因**：影响第 8 周架构与第 10 周实现，不属于本周 spec 范围。
- **下一步计划**：与 C-03 一并写入 ADR-002 评估。

### 8.3 发布职责（已解决）

- **原冲突**：`spec/module-01-qbank.md` v0.1 曾把发布试卷、设置 `startAt/endAt` 写在 `qbank`，与 `contract-v0.1.md` 第 3.1 节和 `mvp1-scope.md` 第 4 节不一致。
- **处理结果**：`qbank` v0.2（PR #19）已移除发布、关闭与时间窗口职责，仅向 `exam` 交接 `DRAFT` 试卷；发布校验见本 spec 的 FR-1、AC-1、AC-8。
- **当前状态**：两份模块 spec 不再冲突，本节保留用于追溯，无需后续动作。

### 8.4 契约缺口：参与范围

- **问题描述**：`Paper` 实体没有班级、参与名单或可见范围字段，但 `context.md` 术语表描述考试“面向指定学生发布”。
- **MVP1 取舍**：不建参与名单，已发布考试对全体学生可见。
- **下一步计划**：若课程要求按班级发布，需先升版契约补充参与范围，再修改本 spec 的 FR-2。
