## 1. 引言

### 1.1 编写目的

- 固化团队对「当前版本要做什么」的共识，消除 v1.3 中已被收敛的三角色、客观题、管理员审核等内容。
- 为架构设计、接口契约、任务拆解与验收提供统一依据。
- 指导六人小组按 `qbank` / `exam` / `grading` 三模块分工，明确跨模块边界与失败语义。
- 让第 9 周任务拆解、第 10～14 周开发与第 11 周答辩都能回溯到同一条需求。

### 1.2 项目背景

本项目为上海师范大学软件工程课程小组项目（6 人）。系统面向高校课程考试场景，教师维护简答/论述题题库并组卷发布，学生在时间窗口内在线作答，系统调用 DeepSeek 按评分点给出建议分，教师逐题复核确认后统一发布成绩。

v1.3 是基于旧版 SRS 的架构导读优化稿，包含三角色、管理员审核、客观题自动判分、题目分类与批量导入等内容。经过第 6～8 周的范围收敛，当前版本已锁定为**两角色、三模块、仅主观题**。本版按当前状态重写。

**与 v1.3 的主要收敛差异**

| 维度 | v1.3 | 本版（v2.0） |
| --- | --- | --- |
| 业务角色 | 学生、教师、管理员 | **仅学生、教师**；管理员不是业务角色 |
| 试卷发布 | 教师提交 → 管理员审核 → 发布 | **教师组卷后直接发布** |
| 题型 | 客观题 + 主观题 | **仅简答题、论述题** |
| 判分 | 客观题自动判分 + 主观题 AI 阅卷 | **无客观题判分**；AI 只给建议分，教师确认 |
| 题库分类 | 学科 → 章节 → 知识点；批量导入 | **不做分类体系与批量导入** |
| 成绩 | 客观题 + 主观题合并；排名 | **教师确认分汇总**；不做排名、统计报表 |
| 模块 | 权限、题库、组卷、审核、考试、自动阅卷、AI 阅卷、成绩 | **qbank、exam、grading 三模块 + 集成横切能力** |
| 技术约束 | 未完全收敛 | 单体应用、MySQL 8、DeepSeek、JWT、Docker；禁 Redis / MQ / 微服务 |

### 1.3 项目目标

当前版本（MVP1）应实现：

1. 教师维护主观题题库，题目包含题干、参考答案、至少 1 个评分点，评分点分值之和等于题目总分。
2. 教师从 `ACTIVE` 题目中组卷，保存为 `DRAFT` 试卷，单题分值继承且不可修改。
3. 教师直接发布考试，设置开始/截止时间；发布后试卷结构、分值与时间窗口不可修改。
4. 学生在时间窗口内限时作答，草稿自动保存，刷新或断线后可续答。
5. 手动交卷或到点由服务端自动交卷；交卷后答卷只读，重复交卷被拒绝。
6. 教师对已提交答卷触发 DeepSeek 初评，AI 按评分点返回命中情况、建议分与理由。
7. 教师逐题采纳、修改或驳回 AI 建议并填写确认分，保留 AI 原建议与复核人、时间。
8. 整场所有已提交答卷的每道题完成复核后，教师统一发布成绩；学生只能查看本人成绩。
9. 全程只有学生、教师两种业务角色；不使用管理员、不做客观题、不做自助注册。

### 1.4 术语与缩略语

| 术语 | 英文 / 缩写 | 定义 |
| --- | --- | --- |
| 主观题 | Subjective Question | 需要文字作答的题目；本系统仅支持简答题 `SHORT_ANSWER`、论述题 `ESSAY` |
| 评分点 | RubricItem | 教师维护的可独立判定的得分要点及分值；MVP1 采用二值判定 |
| 试卷 | Paper | 题目有序集合；**一份试卷即一场考试**，时间窗口写在试卷上 |
| 答卷 | AnswerSheet | 一名学生对一份试卷的一次作答；同一试卷同一学生仅一份 |
| 评分结果 | GradeResult | 一道题在答卷上的 AI 建议分、评分点命中与教师确认分 |
| AI 建议分 | aiScore | DeepSeek 按评分点给出的建议得分，仅作参考，不是正式成绩 |
| 教师确认分 | reviewedScore | 教师逐题复核后的正式得分；**正式成绩以教师确认分为准** |
| 最终成绩 | finalScore | 成绩发布后由各题 `reviewedScore` 汇总；发布前不得写入 |
| 草稿 | DRAFT | 未交卷或未发布的中间状态 |
| 已提交 | SUBMITTED | 答卷已交卷、只读 |
| ADR | Architecture Decision Record | 架构决策记录，记录取舍与后果 |
| Non-Goals | — | 明确不做、可直接拒绝的范围边界 |

## 2. 项目概述

### 2.1 系统定位与范围

**一句话定位**：面向高校课程考试场景的 AI 辅助主观题考试系统。

**MVP1 唯一验收路径**

```
教师登录
  → 建题（题干、参考答案、评分点及分值）
  → 组卷（选 2～5 题，校验分值）
  → 发布考试（设置开始/截止时间）
  → 学生登录 → 限时作答（草稿自动保存）
  → 手动交卷 或 到点服务端自动交卷
  → 教师触发 AI 初评（逐评分点给建议分与理由）
  → 教师逐题复核（采纳 / 修改 / 驳回并留痕）
  → 整场复核完成后教师统一发布成绩
  → 学生查看本人每题得分与复核意见
```

**判定标准（宁小勿大）**：上述 8 步能由 1 名教师、2 名学生完整跑通，即为 MVP1 达标。

**明确不做（Non-Goals，任一出现直接拒绝）**

| 类别 | 不做 |
| --- | --- |
| 题型 | 单选题、多选题、判断题及任何客观题自动判分 |
| 角色与账号 | 管理员角色；学生自助注册；密码找回；账号批量导入 |
| 考务外围 | 监考、人脸识别、防切屏、断网检测、成绩排名、统计报表、通知推送、成绩导出 |
| AI 能力 | AI 出题、AI 错题讲解、AI 自动定分、多模型对比、模型训练 |
| 架构 | 多租户、多学科隔离、移动端 App、第二家大模型、消息队列、Redis、微服务 |
| 题库扩展 | 题库批量导入、题目版本管理、题目共享/协作 |

### 2.2 用户角色与权限

| 角色 | 职责 | 关键权限 | 明确限制 |
| --- | --- | --- | --- |
| 学生 | 参加考试、作答、查看本人成绩 | 窗口内进入考试；保存草稿；交卷；查询本人已发布成绩 | 不可见评分点、参考答案、AI 建议分；不可访问他人答卷与成绩 |
| 教师 | 建题、组卷、发布考试、触发 AI 初评、复核、发布成绩 | 维护本人题库与试卷；查看本人试卷的答卷；复核本人试卷 | 不可跨教师访问；不可修改已交卷答案；不可自动定分 |

**锁定规则**

1. 本版本不含管理员角色；账号初始化与试卷发布职能并入教师。
2. 教师组卷后直接发布，不存在「教师提交 → 管理员审核 → 发布」。
3. 身份与角色一律取自 JWT，不接受请求体传入的 `studentId` / `reviewedBy`。

### 2.3 运行环境与技术约束

| 层次 | 选型 | 约束 |
| --- | --- | --- |
| 前端 | Vue 3（Composition API + Vite） | 仅 Web；不做 App / 小程序 |
| 后端 | Java 21 + Spring Boot 4.1 | 单体应用，按模块分包 |
| 数据库 | MySQL 8（utf8mb4） | 唯一业务持久化存储 |
| AI | DeepSeek（OpenAI 兼容 Chat Completions） | 仅后端 `AIService` 调用 |
| 鉴权 | JWT | 密钥与有效期从环境变量读取 |
| 部署 | Docker | 前后端与数据库可容器化启动 |

**硬性约束**

1. 前后端分离，前端通过 REST + JSON 调用后端，不在服务端渲染页面。
2. 不引入 Redis、消息队列、第二数据库、微服务、规则引擎。
3. DeepSeek API Key 只通过后端环境变量注入，禁止前端直连、禁止入库。
4. AI 调用必须经过统一 `AIService`，禁止在业务代码中散落模型调用。
5. AI 输出必须按约定 JSON 结构解析，失败按异常处理，不得静默吞掉。
6. 关键操作（交卷、自动交卷、成绩发布）必须幂等；时间以服务端为准。
7. 接口契约先行：先定契约再并行开发，契约变更走 ADR 与独立 PR。

### 2.4 项目假设与限制

**已确定**

- 账号由教师初始化；不开放学生自助注册与密码找回。
- 一份试卷对应一场考试；复用试卷发布多场属于后续版本。
- MVP1 不建班级、参与名单；已发布考试对全体学生可见（见 9.2 G-01/G-09）。
- 题型仅简答、论述；评分点采用二值判定（命中得满分，未命中得 0 分）。
- 成绩发布由 grading 负责；考试发布由 exam 负责，两者不是同一个状态。
- 第 8 周只做架构、接口、ADR 与探针，不写业务生产代码。

**建议（非强制，待确认）**

- 单场考试并发按 30～60 人设计（TBD-07）。
- 浏览器兼容范围为 Chrome / Edge 最新稳定版（待确认）。
- 部署环境为课程演示环境，单实例运行（待确认）。

### 2.5 系统结构与模块协作

```
qbank（题目 + 评分点 + DRAFT 试卷）
   │  交接 DRAFT 试卷
   ▼
exam（发布考试、窗口、作答、草稿、交卷）
   │  交接 SUBMITTED 答卷
   ▼
grading（AI 建议分 → 教师复核 → 成绩发布）
   │
   ▼
学生查看本人成绩

横切：integration（JWT、统一错误码、AIService、跨模块契约、端到端联调）
```

| 模块 | 职责 | 明确不负责 | 当前主笔 / 协作 |
| --- | --- | --- | --- |
| `qbank` | 题目、评分点、组卷为 `DRAFT` 试卷 | 考试发布、时间窗口、作答、AI 评分 | 孙宇萱（主笔）、周裔 |
| `exam` | 发布考试、作答、草稿保存、手动/自动交卷 | 题目维护、AI 评分、成绩发布 | 钱斓轩（主笔）、李昕彤 |
| `grading` | AI 初评、教师复核、成绩发布、学生查询 | 组卷、考试发布、修改答案 | 左恩东、王麒博（按周任务认领） |
| `integration` | 登录与 JWT、统一错误码、`AIService`、契约、联调 | 不代替模块实现业务规则 | 李昕彤 |

**当前阶段**：第 8 周，架构基线与 SRS 草案评审中；`src/` 无业务代码，技术探针只放 `docs/spike/`。

## 3. 功能需求

> 编号规则：`FR-xx` 为本文件内的需求编号；模块级细节与验收用例以 `spec/` 为准。
> 所有功能默认要求服务端鉴权与归属校验；错误响应必须含 `code` 与 `message`。

### 3.1 用户与权限管理（integration）

| 编号 | 需求 | 角色 | 主流程与规则 | 异常 / 错误码 |
| --- | --- | --- | --- | --- |
| FR-01 | 登录与身份认证 | 学生、教师 | 账号密码登录；密码 BCrypt 校验；成功后返回 JWT 与角色；后续请求使用 `Authorization: Bearer <JWT>` | 未登录/令牌失效 401 `UNAUTHORIZED`；参数缺失 400 |
| FR-02 | 角色与资源归属控制 | 学生、教师 | 服务端按 JWT 身份校验资源归属：学生仅本人答卷与成绩；教师仅本人创建的试卷与答卷 | 越权 403 `FORBIDDEN`；不得仅靠前端隐藏 |
| FR-03 | 成绩隐私与 AI 结果隔离 | 学生 | 成绩发布前学生不可查询；发布后仅返回本人逐题 `reviewedScore` 与 `reviewComment`；不返回 `aiScore` / `aiReason` / `rubricHits` | 未发布 403 `SCORE_NOT_PUBLISHED`；越权 403 `FORBIDDEN` |

### 3.2 题库管理（qbank）

| 编号 | 需求 | 角色 | 主流程与规则 | 异常 / 错误码 |
| --- | --- | --- | --- | --- |
| FR-04 | 主观题录入与编辑 | 教师 | 支持简答/论述题；字段：题干、参考答案、总分、评分点；新建题目默认 `DRAFT` | 题目不存在 404 `QUESTION_NOT_FOUND`；参数非法 400 |
| FR-05 | 评分点管理 | 教师 | 每题至少 1 个评分点；每个评分点含描述、分值、顺序；评分点分值之和必须等于题目总分；二值判定 | 分值不匹配 409 `RUBRIC_SCORE_MISMATCH` |
| FR-06 | 评分点表述校验 | 教师 | 保存时检测「以及、等等、酌情、其他合理」等不可判定表述，命中即拒绝 | 409 `RUBRIC_DESCRIPTION_VAGUE` |
| FR-07 | 题目状态管理 | 教师 | `DRAFT` → `ACTIVE` → `ARCHIVED`；仅 `ACTIVE` 可被组卷；已发布试卷引用题目的历史一致性见 9.2 C-01 | 状态非法 409；参数非法 400 |

### 3.3 组卷管理（qbank）

| 编号 | 需求 | 角色 | 主流程与规则 | 异常 / 错误码 |
| --- | --- | --- | --- | --- |
| FR-08 | 组卷 | 教师 | 从本人 `ACTIVE` 题目中选题；维护顺序；单题分值继承题目 `totalScore`，组卷时不可修改；保存为 `DRAFT` | 使用非 `ACTIVE` 题目 409；分值不一致 409 `PAPER_SCORE_MISMATCH` |
| FR-09 | 试卷草稿与总分校验 | 教师 | 试卷至少 1 题；`totalScore` 等于各题分值之和；本阶段不设置 `startAt/endAt`，由 exam 发布时设置；组卷时保存基线快照 | 空试卷 409 `EMPTY_PAPER`；总分不一致 409 `PAPER_SCORE_MISMATCH` |

> **快照补充（ADR-001 提议）**：草稿阶段提供只读对比接口（前端第 10 周实现），用于查看组卷时的基线快照与当前题目差异；发布时基线快照随 `Paper.status=PUBLISHED` 冻结为正式快照。评审通过前不作为已冻结需求。

### 3.4 考试发布（exam）

| 编号 | 需求 | 角色 | 主流程与规则 | 异常 / 错误码 |
| --- | --- | --- | --- | --- |
| FR-10 | 发布考试 | 教师 | 仅 `DRAFT` 试卷可发布；发布前校验至少 1 题、总分一致、`startAt < endAt` 且 `endAt` 未过期；发布后 `PUBLISHED`，记录服务端 `publishedAt`；结构、每题分值与时间窗口不可修改 | 409 `EMPTY_PAPER` / `PAPER_SCORE_MISMATCH` / `INVALID_EXAM_WINDOW` |
| FR-11 | 考试可见性 | 学生 | 仅 `PUBLISHED` 考试对学生可见；MVP1 对全体学生可见，不建参与名单 | 未开始 403 `EXAM_NOT_STARTED`；已关闭 403 `EXAM_CLOSED` |
| FR-12 | 考试关闭 | 系统 | 到达 `endAt` 后试卷进入 `CLOSED`，学生不可再进入或作答 | 窗口外操作 403 `EXAM_CLOSED` |

### 3.5 在线考试与答卷（exam）

| 编号 | 需求 | 角色 | 主流程与规则 | 异常 / 错误码 |
| --- | --- | --- | --- | --- |

## 5. 主要业务流程

### 5.1 建题 → 组卷 → 发布

```
教师登录
  → 建题（题干 / 参考答案 / 评分点，校验分值合计与模糊表述）
  → 题目置 ACTIVE
  → 组卷（选 ACTIVE 题目，单题分值继承，保存 DRAFT）
  → 发布考试（设置 startAt / endAt，校验至少 1 题、总分一致、窗口合法）
  → 试卷 PUBLISHED，学生对全体可见
```

**关键点**：没有管理员审核环节；发布后试卷结构、分值与时间窗口不可修改。

### 5.2 考试 → 作答 → 交卷

```
学生登录 → 进入考试（窗口内，创建 DRAFT 答卷）
  → 作答（自动保存草稿，刷新可续答）
  → 手动交卷 或 到达 endAt 服务端自动交卷
  → 答卷 SUBMITTED、只读
```

**关键点**：交卷以服务端时间为准；交卷请求携带全部答案；重复交卷返回 409；交卷后不能再保存。

### 5.3 AI 初评 → 教师复核 → 成绩发布

```
教师对已提交答卷触发 AI 初评
  → AIService 调 DeepSeek，按评分点返回命中与建议分
  → 严格校验输出；成功写 GradeResult（aiStatus=SUCCEEDED）
  → 教师逐题复核（采纳 / 修改 / 驳回，填写 reviewedScore）
  → 整场所有已提交答卷的每道题均复核
  → 教师统一发布成绩（finalScore = 各题 reviewedScore 之和）
  → 学生查看本人逐题确认分与复核意见
```

**关键点**：AI 只给建议分；教师确认分是正式成绩；`reviewedScore=0` 是有效确认；发布前学生不可见。

### 5.4 AI 阅卷异常 → 人工复核

```
AI 超时 / 非法 JSON / 评分点不匹配 / 分数越界
  → 该题 aiStatus=FAILED，不写可用 aiScore
  → 教师人工复核并填写 reviewedScore
  → 不影响其他题与整场流程
```

**关键点**：失败不等于 0 分；不无限重试；人工通道始终可用；迟到 AI 结果不得覆盖确认分。

### 5.5 并发交卷与自动交卷

```
手动交卷 / 网络重试 / 到点自动交卷同时到达
  → 唯一约束 (paperId, studentId)
  → 条件更新 status=DRAFT
  → 仅一个请求成功迁移为 SUBMITTED
  → 其余请求返回 409 EXAM_ALREADY_SUBMITTED
```

**关键点**：以数据库唯一约束 + 条件更新保证幂等；不依赖应用层内存锁。

## 6. 外部接口需求

### 6.1 用户界面

| 端 | 页面 / 能力 |
| --- | --- |
| 学生端 | 登录；考试列表；考试作答页（倒计时、草稿自动保存）；交卷确认；本人成绩页（逐题确认分与复核意见） |
| 教师端 | 登录；题库管理；建题（评分点）；组卷；发布考试；答卷与评分状态；逐题复核；成绩发布 |

不提供管理员端。前端只消费 API，不判断业务规则；身份字段不通过请求体提交。

### 6.2 数据库接口

系统需持久化保存：

- 用户与角色（学生 / 教师）；
- 题目、评分点（含分值与顺序）；
- 试卷与组卷明细（题目、顺序、每题分值、总分、时间窗口）；
- 答卷与逐题答案（草稿与最终提交）；
- 评分结果（AI 建议分、逐点命中、教师确认分、复核信息、调用审计字段）；
- 成绩发布状态（由 G-06 确定存储方式）。

具体物理表结构在实现阶段设计；逻辑实体与约束见第 7 章。

### 6.3 外部 AI 接口

| 项 | 要求 |
| --- | --- |
| 协议与端点 | DeepSeek，OpenAI 兼容 Chat Completions（`POST /chat/completions`） |
| 认证 | API Key 置于请求头 `Authorization: Bearer <API_KEY>`，仅后端环境变量注入 |
| 输入 | 题干、参考答案、评分点（ID、描述、分值）、题目总分、学生文字答案 |
| 输出 | 结构化 JSON：逐评分点命中 `rubricHits[]`（`rubricItemId`、`hit`、`score`、`reason`）、`aiScore`、`aiReason`；物理字段待 C-04 固化 |
| 校验 | 评分点 ID 完整、无重复、无陌生 ID；二值分数与 `hit` 一致；逐点合计等于 `aiScore`；范围在 `[0, 题目分值]`；任一失败整题拒绝 |
| 超时与重试 | 后端超时 30 秒；自动重试最多 1 次；总尝试 ≤ 3 次；失败置 `FAILED`，转人工 |
| 降级 | AI 故障不影响考试、交卷与人工复核；不自动记 0 分 |
| 审计 | 持久化模型名、提示词版本、原始响应、调用人/时间；原始响应不返回学生端 |
| 安全 | 学生答案作为待评分内容，不得改变评分规则或越权调用系统操作 |

### 6.4 系统内部接口

| 项 | 要求 |
| --- | --- |
| 基础路径 | `/api/v1` |
| 数据格式 | JSON，UTF-8 |
| 鉴权 | JWT；身份与角色取自令牌 |
| 时间 | ISO-8601 带时区；一律以服务端为准 |
| 成功响应 | 单资源返回对象；列表返回数组；创建用 201 |
| 失败响应 | `{ "code": "...", "message": "...", "requestId": "..." }`；禁止用 200 表示失败 |

模块接口清单与路径以 `docs/architecture.md` 第 6 节为准；模块组评审确认后冻结。

| `INVALID_REVIEWED_SCORE` | 400 | 确认分非整数或超出题目分值范围 | grading | 待契约 v0.2 |

约定：所有错误响应体必须含 `code` 与 `message`，不得为空；禁止用 200 表示业务失败。

## 7. 数据需求

### 7.1 核心实体

| 实体 | 说明 | 关键字段 | 产生 / 消费 |
| --- | --- | --- | --- |
| `Question` 题目 | 简答或论述题 | `id`、`type`、`stem`、`referenceAnswer`、`rubric[]`、`totalScore`、`status`、`createdBy`、时间戳 | qbank → qbank / grading |
| `RubricItem` 评分点 | 可独立判定的得分要点 | `id`、`questionId`、`description`、`score`、`order` | qbank → grading |
| `Paper` 试卷 | 一份试卷即一场考试 | `id`、`title`、`items[]`、`totalScore`、`status`、`startAt`、`endAt`、`publishedAt`、`createdBy` | qbank → exam |
| `PaperItem` 组卷明细 | 试卷内题目顺序、分值与基线快照 | `questionId`、`order`、`score`（等于题目总分）；快照字段：`type`、`stem`、`referenceAnswer`、`totalScore`、`rubric[]`（待 ADR-001 通过） | qbank → exam |
| `AnswerSheet` 答卷 | 一名学生的一次作答 | `id`、`paperId`、`studentId`、`answers[]`、`status`、`startedAt`、`submittedAt`、`submitType`、`finalScore` | exam → grading |
| `Answer` 逐题答案 | 学生对某题的作答 | `questionId`、`content`、`savedAt` | exam → grading |
| `GradeResult` 评分结果 | 一道题的 AI 与教师结果 | `id`、`answerSheetId`、`questionId`、`aiStatus`、`rubricHits[]`、`aiScore`、`aiReason`、`reviewedScore`、`reviewComment`、`reviewedBy`、`reviewedAt`、审计字段 | grading → 教师 / 学生 |
| `RubricHit` 评分点命中 | AI 逐点判断 | `rubricItemId`、`hit`、`score`、`reason` | grading |

**不单独建实体**：

- 不建「考试」实体：一份试卷即一场考试，时间窗口写在试卷上。
- 不建「成绩表」：成绩是答卷各题 `reviewedScore` 的汇总，避免双写。
- 不建「试卷审核记录」：不存在管理员审核流程。

### 7.2 状态机

**题目**

```
DRAFT ──启用──► ACTIVE ──归档──► ARCHIVED
```

**试卷 / 考试**

```
DRAFT ──教师发布──► PUBLISHED ──到达 endAt──► CLOSED
```

**答卷**

```
DRAFT ──手动/自动交卷──► SUBMITTED
```

**单题评分**

```
NOT_STARTED ──教师触发──► PENDING ──AI 成功──► SUCCEEDED
                                  └──AI 失败──► FAILED ──人工重试──► PENDING
SUCCEEDED / FAILED ──教师复核──► 写入 reviewedScore（状态不新增枚举）
```

**成绩发布**

```
NOT_READY ──全部已提交答卷的每题均有 reviewedScore──► READY ──教师发布──► PUBLISHED
```

### 7.3 关键数据约束

| 编号 | 约束 |
| --- | --- |
| DC-01 | 题目至少 1 个评分点；评分点分值之和等于题目 `totalScore` |
| DC-02 | 试卷至少 1 题；`totalScore` 等于各题分值之和；单题分值等于题目 `totalScore` |
| DC-03 | `startAt < endAt`；发布时 `endAt` 未过期；发布后结构、分值与窗口不可修改 |
| DC-04 | 同一学生同一试卷只能有一份答卷：唯一约束 `(paperId, studentId)` |
| DC-05 | 交卷幂等：重复请求不得生成第二份答卷或改变已提交内容 |
| DC-06 | 同一答卷同一题只有一份 `GradeResult`：唯一约束 `(answerSheetId, questionId)` |
| DC-07 | AI 输出必须整题通过校验；评分点 ID 全匹配、二值分数一致、合计等于 `aiScore`、范围合规 |
| DC-08 | `reviewedScore` 为 `[0, 题目分值]` 内整数；`0` 分是有效确认 |
| DC-09 | 复核保留 `aiScore` 原值，只写 `reviewedScore`；迟到 AI 响应不得覆盖确认分 |
| DC-10 | 成绩发布前不得写入 `finalScore`；发布后 `finalScore` 等于各题 `reviewedScore` 之和 |
| DC-11 | 成绩发布前学生不可见任何分值；发布后仅本人可见 |
| DC-12 | 密码 BCrypt 存储；时间字段一律服务端生成 |
| DC-13 | 组卷时保存基线快照，发布时随 `Paper.status=PUBLISHED` 冻结为正式快照；下游只读快照（ADR-001 提议，待评审通过后生效） |
| DC-14 | 题目被任一 `PUBLISHED` 试卷引用时禁止修改，返回 409 `QUESTION_ALREADY_USED`（锁题策略，待契约 v0.2 登记） |

### 7.4 权限与可见性

| 资源 | 学生 | 教师 |
| --- | --- | --- |
| 题目 / 评分点 | 作答时可见题干；不可见评分点与参考答案 | 仅本人创建 |
| 试卷 / 考试 | 仅已发布且在时间窗口内 | 仅本人创建 |
| 答卷 | 仅本人 | 仅本人试卷的答卷 |
| AI 结果（`aiScore` / `aiReason` / `rubricHits`） | 不可见 | 仅本人试卷 |
| 成绩（`reviewedScore` / `reviewComment`） | 发布后仅本人可见 | 仅本人试卷 |

### 7.5 数据版本与历史一致性

已发布试卷的结构、分值与时间窗口不可修改。题目本体与评分点的历史取值由 **C-01 / ADR-001** 处理，当前提案为：

- **方案 A**：动态引用题目当前版本（不采用，历史会漂移）；
- **方案 B（提议）**：组卷时保存基线快照，草稿阶段提供只读对比；发布时基线快照随 `Paper.status=PUBLISHED` 冻结为正式快照，下游只读快照；
- **方案 C**：版本号 + 历史查询（属 v2，触碰 MVP1 Non-Goals）。

配套的锁题策略：题目被任一 `PUBLISHED` 试卷引用时禁止修改，返回 409 `QUESTION_ALREADY_USED`。ADR-001 通过前，任何实现不得把方案 B 或锁题策略当作已冻结需求；`architecture.md` 6.2 的相关行为同样标注为待决议。

## 8. 验收标准

### 8.1 验收准备与判定规则

- 准备 1 名教师账号、2 名学生账号；题库初始为空。
- 按第 2.1 节唯一演示路径执行，允许使用构造数据，但不得绕过接口直接改库。
- 每个用例必须记录：输入、实际响应、数据库状态、对应 FR / AC。
- 判定规则：主流程完整跑通 + 异常路径返回正确错误码且无副作用，才算通过。
- 不要求评分准确率作为验收项；AI 只验证结构化输出与降级路径。
